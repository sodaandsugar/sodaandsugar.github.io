    Chapter 6 Mass-Storage Structure¶

    本章讨论大容量存储（mass storage）如何被操作系统组织和管理。核心主线是：硬件以 block 为单位提供持久化存储，OS 需要在性能、可靠性、空间管理和上层文件系统之间建立清晰的抽象。

    本章主线

    • 磁盘以 logical block 作为最小传输单位，对外呈现一维 LBA 空间
    • 磁盘访问时间主要由 seek time、rotational latency、transfer time 和 controller overhead 组成
    • Disk scheduling 试图减少磁头移动，提高访问时间和带宽
    • SSD / NAND Flash 没有机械移动，但有 erase-before-write、wear leveling、FTL 等新问题
    • Disk management 包括 physical formatting、partition、logical formatting、boot block、bad block 处理和 swap space
    • Disk attachment 可分为 host-attached storage、NAS 和 SAN
    • RAID 通过 striping、mirroring、parity 在性能和可靠性之间折中

    1 Overview of Mass Storage Structure¶

    磁盘长期是计算机系统中最主要的 secondary storage。它容量大、成本低、断电后数据仍能保留，但访问延迟远高于主存。

    Magnetic Disk 的基本特征
    • Hard disk 是最常见的磁盘形式，有些磁盘可以拆卸
    • Drive 通过 I/O bus 连接到计算机，例如 USB、SCSI、EIDE、SATA
    • 盘片旋转速度约为每秒 60 ~ 250 圈
      • 7200 RPM = 120 RPS
    • 历史上磁盘盘片尺寸从 .85 inch 到 14 inch 不等
    • 现代常见尺寸包括 3.5 inch、2.5 inch、1.8 inch
    • 单盘容量从几十 GB 到数 TB，且仍在增长

    存储系统里的核心矛盾

    Secondary storage 便宜且容量大，但慢且可能失效。因此 OS 不能只把它当成“大内存”，还必须考虑调度、缓存、错误处理、冗余和文件系统布局。

    2 Disk Structure¶

    磁盘驱动器对上层暴露为一维的 logical block array，每个 logical block 是最小传输单位。上层通常只关心 block number，不直接管理柱面、磁道和扇区。

    LBA 到物理扇区的典型映射

    Logical blocks 会顺序映射到磁盘 sectors：

    1. sector 0 是最外层 cylinder 的第一条 track 上的第一个 sector
    2. 先沿当前 track 顺序映射
    3. 再映射同一 cylinder 中剩余 tracks
    4. 然后从外层 cylinder 逐步走向内层 cylinder

    理想情况下，logical address 到 physical address 的转换应很简单；但 bad sectors、spare sectors、firmware remapping 等机制会让真实映射更复杂。

    磁盘的基本物理结构包括 platter、track、sector、cylinder、disk arm 和 disk head。同一半径上的所有 tracks 组成一个 cylinder。

    为什么 OS 通常使用 LBA

    现代磁盘内部可能有坏块替换、缓存、可变扇区密度和 firmware 调度。OS 直接操作 CHS（Cylinder-Head-Sector）既复杂又不稳定，因此更常把磁盘看成线性的 block device。

    3 Magnetic Disk Performance¶

    一次磁盘 I/O 的时间由多个部分组成，其中机械移动通常占主要成本。

    Positioning Time

    Positioning time 是把磁头移动到目标 sector 所需的时间，也称 random-access time：

    \[ positioning\ time = seek\ time + rotational\ latency \]
    • Seek time：移动 disk arm 到目标 cylinder 的时间
    • Rotational latency：等待目标 sector 转到 disk head 下方的时间
    常见性能指标
    • Transfer rate：数据在 drive 与 computer 之间传输的速率
      • 理论接口速率可到数 Gb/s
      • 实际有效吞吐通常低于理论值
    • Seek time：典型机械硬盘约 3 ms ~ 12 ms

    • Rotational latency：

      \[ one\ rotation = \frac{60}{RPM} \]

      平均 rotational latency 约为半圈时间：

      \[ average\ latency = \frac{1}{2} \times \frac{60}{RPM} \]

    Average Access Time

    若最快磁盘平均 seek time 约为 3 ms，平均 rotational latency 约为 2 ms，则平均 access time 约为 5 ms。

    若普通桌面盘平均 seek time 约为 9 ms，7200 RPM 下平均 rotational latency 约为：

    \[ \frac{1}{2} \times \frac{60}{7200} \approx 4.17 ms \]

    课件给出的慢盘示例为：

    \[ 9 ms + 5.56 ms = 14.56 ms \]

    Average I/O Time

    一次 I/O 不只包含定位，还包含传输和控制器开销：

    \[ average\ I/O\ time = average\ access\ time + \frac{data\ size}{transfer\ rate} + controller\ overhead \]

    例如读取 4 KB block，7200 RPM，平均 seek time 5 ms，controller overhead 0.1 ms，则主要时间来自 seek 与 rotation，真正传输 4 KB 的时间通常很小。

    4 Disk Scheduling¶

    OS 负责高效使用磁盘硬件。对磁盘而言，主要目标是：

    • 降低 access time，尤其是 seek time
    • 提高 disk bandwidth
    • 在多个请求之间保持合理公平性

    Disk Bandwidth

    Disk bandwidth 是单位时间完成的数据传输量：

    \[ bandwidth = \frac{total\ bytes\ transferred}{time\ from\ first\ request\ to\ last\ completion} \]

    Disk scheduling 决定 pending disk requests 中下一个服务哪个请求。若磁盘空闲，请求可以立即执行；若磁盘忙，OS 或控制器会把请求放入队列。

    一个 disk request 通常包含
    • I/O mode：读或写
    • disk address：目标 LBA / sector
    • memory address：数据要读入或写出的内存位置
    • sector count：要传输多少 sectors

    调度算法只有在队列中有多个请求时才有意义。现代设备常由 controller firmware 在内部做排序，OS 只提供 LBA 请求。

    本章课件用如下 cylinder 请求队列作为例子：

    98, 183, 37, 122, 14, 124, 65, 67

    假设 cylinder 范围是 [0, 199]，初始磁头位置为 53。

    4. 1 FCFS¶

    FCFS（First-Come First-Served）按请求到达顺序服务，最简单，也最公平。

    优点 缺点
    每个请求都有机会被服务 不优化 seek time
    不会 indefinite postponement 磁头可能来回大幅移动
    实现最简单 平均响应时间可能很差
    课件示例

    对 98,183,37,122,14,124,65,67，初始位置 53，FCFS 的 total head movement 为 640 cylinders。

    4. 2 SSTF¶

    SSTF（Shortest Seek Time First）每次选择离当前磁头位置最近的请求。

    SSTF 的性质

    • 类似 CPU scheduling 中的 SJF
    • 通常能明显减少总 seek distance
    • 可能导致远处请求长期等待，存在 starvation 风险
    • 它是贪心算法，不保证全局最优
    课件示例

    同样的请求队列下，SSTF total head movement 为 236 cylinders，明显少于 FCFS。

    4. 3 SCAN¶

    SCAN 又称 elevator algorithm。磁头像电梯一样沿一个方向移动，沿途服务请求；到达磁盘一端后再反向移动并继续服务。

    优点 缺点
    等待时间比 SSTF 更稳定 到达一端前，反方向的新请求需要等待
    不容易让远端请求长期饥饿 会移动到端点，即使端点附近没有请求
    适合持续 I/O 负载 两端附近请求的等待特性与中间不同

    4. 4 C-SCAN¶

    C-SCAN（Circular SCAN）把 cylinders 视为一个循环列表。磁头只在一个方向服务请求；到达末端后快速返回起点，返回途中不服务请求。

    C-SCAN 的目标

    C-SCAN 牺牲一部分磁头移动距离，换取更均匀的等待时间。因为所有请求都从同一个方向被扫描，不会出现 SCAN 中“两端服务频率不同”的问题。

    4. 5 LOOK and C-LOOK¶

    SCAN / C-SCAN 会移动到磁盘端点，即使端点附近没有请求。LOOK 和 C-LOOK 的改进是：磁头只移动到当前方向上的最后一个请求位置，然后就反向或跳转。

    算法 基础算法 改进点
    LOOK SCAN 不走到物理端点，只走到该方向最后一个请求
    C-LOOK C-SCAN 不跳到物理起点，只跳到最低请求位置

    4. 6 Selecting Disk-Scheduling Algorithm¶

    磁盘调度算法的性能取决于请求数量、请求分布、磁盘类型和 workload。

    选择原则

    • SSTF 常作为默认选择，因为简单且效果通常不错
    • LOOK 和 C-LOOK 在 heavy I/O load 下通常表现更好
    • 调度器应作为可替换模块实现，便于针对设备和 workload 调整
    • 文件分配方式和 metadata 布局会影响调度效果
    File system 对磁盘调度的影响

    File system 会努力提高 spatial locality，把相关数据和 metadata 尽量放近。若文件系统布局很差，即使调度算法优秀，也可能被迫处理大量远距离 seek。

    5 Nonvolatile Memory Devices¶

    若非易失性存储设备对外表现得像 disk drive，通常称为 SSD（Solid-State Disk）。其他形式还包括 USB drive、DRAM disk replacement、主板上的 surface-mounted storage 等。

    特性 HDD SSD / NVM
    机械移动 有 disk arm 和 platter 无 moving parts
    seek time / rotational latency 明显存在 基本不存在
    FCFS 效果 不一定好 通常可接受
    每 MB 成本 低 更高
    容量 通常更大 逐渐增大但成本较高
    寿命问题 机械磨损 写入次数有限

    为什么 SSD 很快但仍需要管理

    SSD 没有机械定位延迟，但 NAND Flash 不能原地覆盖，必须先擦除再写入。擦除粒度大于写入粒度，并且每个 cell 的可擦写次数有限。

    5. 1 NAND Flash Constraints¶

    NAND Flash 通常按 page 读写，但按更大的 block 擦除。

    课件示例

    假设：

    • block size = 64 KB
    • page size = 4 KB
    • 一个 block 包含 16 个 pages

    写入时不能直接 overwrite 某个 page。若需要修改已有数据，controller 往往写到新 page，再把旧 page 标记为 invalid，之后由 garbage collection 回收旧 block。

    DWPD

    Flash cell 只能擦除有限次数，课件给出数量级约 100,000 次。SSD 寿命常用 DWPD（Drive Writes Per Day）描述。

    例如 1 TB NAND drive 标称 5 DWPD，表示在保修期内预计每天可写入约 5 TB 数据而不失效。

    5. 2 Flash Translation Layer¶

    由于不能原地覆盖，SSD controller 需要维护 FTL（Flash Translation Layer），把上层 LBA 映射到真实 flash pages。

    FTL 与 Controller 的职责
    • 记录哪些 logical blocks 当前有效
    • 把新写入映射到空闲 page
    • 把旧 page 标记为 invalid
    • 运行 garbage collection，把仍有效的数据搬到其他位置
    • 擦除全 invalid 或可回收的 block
    • 保留 over-provisioning 空间作为 GC 工作区
    • 做 wear leveling，让写入尽量均匀分布到所有 cells

    SSD 的性能陷阱

    当空闲 block 充足时，写入可以很快；当 invalid pages 很多但 free blocks 不够时，controller 必须先搬迁有效数据并擦除 block，写延迟会明显上升。

    5. 3 Magnetic Tape¶

    Magnetic tape 是早期重要的 secondary storage，如今主要用于 backup 和归档。

    特性 说明
    容量 大，课件给出 200 GB ~ 1.5 TB 量级
    随机访问 很慢，需要 wind / rewind
    顺序传输 一旦数据到达 head 下方，传输速率可接近磁盘，如 140 MB/s
    数据持久性 较好，适合长期备份

    6 Disk Management¶

    Disk management 关注如何把裸设备变成 OS 和文件系统可使用的存储空间。

    6. 1 Formatting and Partitioning¶

    Physical formatting 会把磁盘划分成 controller 能读写的 sectors。每个 sector 通常包含 header、data 和 ECC。

    Physical Formatting
    • sector 内部有 metadata 和 error correction code
    • 常见 data payload 是 512 bytes
    • 新设备也可能使用更大的 sector，如 4 KB

    OS 还需要在磁盘上记录自己的数据结构：

    • Partition disk：把磁盘划成若干 cylinder groups / partitions，每个 partition 可视为一个 logical disk
    • Logical formatting：在 partition 上创建文件系统
    • Reserved sectors：某些 FS 预留 spare sectors 处理 bad blocks
    • Clusters：FS 可把多个 blocks 组合成 cluster，提高吞吐
    • Boot sector：若 partition 包含 OS image，需要初始化 boot sector

    6. 2 Device Names and Partitions¶

    Linux 中不同磁盘类型有传统设备命名约定。

    设备类型 典型命名 示例
    IDE /dev/hda 到 /dev/hdd /dev/hda1 表示第一块 IDE 盘的第一个分区
    SCSI / SATA / USB storage /dev/sdX /dev/sda1、/dev/sdb1

    Partition Number

    分区编号通常从 1 开始，例如 /dev/sda1。传统 MBR 最多支持 4 个 primary partitions；若需要更多分区，需要使用 extended partition 和 logical partitions，logical partition 编号通常从 5 开始。

    6. 3 Mount, Boot Block and Raw Disk¶

    Root partition 包含 OS，其它 partitions 可以放其它 OS、其它 file systems，或作为 raw device 使用。

    Mount 时 OS 做什么
    • boot 时挂载 root partition
    • 其它 partition 可自动挂载或手动挂载
    • mount 时检查 file system consistency
      • metadata 不正确则尝试修复后再挂载
      • metadata 正确则加入 mount table
    • 挂载成功后，用户才能通过目录树访问该文件系统

    Boot block 可以指向 boot volume，或指向 boot loader 所在 blocks。Boot loader 至少要知道如何从文件系统中定位、加载并启动 kernel。

    Raw Disk Access

    有些应用希望自己管理 block，例如数据库系统。它们可能使用 raw disk access，让 OS file system 尽量不参与数据布局、缓存和锁管理。

    Bad Blocks

    磁盘可能出现坏块。常见方法包括 sector sparing：预留备用扇区，当某 sector 损坏时，由 controller 或 OS 把逻辑地址重映射到备用 sector。

    6. 4 Swap-Space Management¶

    Swap space 用于在 DRAM 不足时，把整个进程或部分 pages 暂时移动到 secondary storage。

    Swap Space 管理目标

    • Secondary storage 远慢于 DRAM，因此 swap 性能必须优化
    • 可以有多个 swap spaces，分散单个设备上的 I/O 压力
    • 专用 swap partition 通常比普通文件中的 swap 更直接
    • 使用 swap file 更方便扩容和管理

    Linux 的 swap 数据结构会记录某个 swap slot 是否空闲，以及该 slot 被哪些进程 / 页面映射。课件中用 0 表示未使用，用非零值表示被映射使用。

    7 Disk Attachment¶

    磁盘可以通过本地总线、网络文件协议或专用存储网络接入计算机。

    7. 1 Host-Attached Storage¶

    Host-attached storage 通过 I/O bus 直接连接到主机。

    常见接口
    • SCSI（Small Computer System Interface）
      • 一条 cable 上可接多个 devices
      • SCSI initiator 发起操作
      • SCSI target 执行任务
      • 每个 target 可包含多个 logical units
      • Linux 常用 /dev/sda 表示 SCSI disk
    • IDE（Integrated Drive Electronics）
      • Linux 传统上用 /dev/hda 表示 IDE disk
    • Fibre Channel
      • 高速串行总线
      • 可形成 switched fabric
      • 常用于 SAN interconnection

    7. 2 Network-Attached Storage¶

    NAS（Network-Attached Storage）通过网络提供文件系统访问，而不是通过本地 bus 暴露 block device。

    NAS 的特点

    • Client 远程挂载 server 上的 file system
    • 常见协议包括 NFS、CIFS
    • 通常基于 RPC 实现
    • 常跑在 TCP 或 UDP/IP 网络上
    • iSCSI 则是在 IP 网络上传输 SCSI protocol

    7. 3 Storage Area Network¶

    SAN（Storage Area Network）是连接 servers 和 storage units 的专用高速网络。

    SAN 的动机
    • 大规模 storage traffic 会占用普通 data network 带宽，因此需要分离
    • TCP/IP stack 对存储访问不一定最高效
    • SAN 常使用高速互连和专门协议
    • 多个 hosts 和 storage arrays 可以接入同一 SAN
    • 服务器集群可以共享同一套 storage
    • Storage 可动态分配给 hosts

    8 RAID Structure¶

    单块磁盘便宜但可能失效，且吞吐有限。RAID（Redundant Array of Independent Disks）把多块磁盘组合起来，用冗余提高可靠性，用并行提高吞吐。

    RAID 的两个目标

    • Reliability：一块磁盘失效时仍能恢复数据
    • Speed：把数据分散到多块盘上并行读写，聚合带宽

    RAID 可以由 OS 在多块 bus-attached disks 上实现，也可以由硬件 RAID controller 实现，还可以作为独立 RAID array box 提供。

    8. 1 Mirroring, Striping and Parity¶

    RAID 的基本技术可以自由组合。

    技术 做法 作用
    Data mirroring 多块磁盘保存相同数据 提高可靠性，写入要写多个副本
    Data striping 数据拆分到多块磁盘 提高并行读写带宽
    Parity / ECC 保存可恢复丢失数据的校验信息 用较少冗余恢复单盘或多盘失效

    8. 2 RAID Levels¶

    RAID 技术组合被称为不同 levels。课件要求掌握常见等级：0、1、1+0、5、5+0、6、6+0，并了解 RAID 2 基本思想但它基本不用。

    8. 3 RAID 0¶

    RAID 0 把数据均匀拆分到两块或多块磁盘上，使用固定 strip size，但没有 parity，也没有 redundancy。

    RAID 0 的关键风险

    RAID 0 只提升性能和容量呈现，不提升可靠性。任一磁盘失效都可能导致整个 RAID 0 上的数据不可用。

    优点 缺点
    多盘并行，顺序读写带宽高 无冗余
    对外像一个更大的磁盘 单个 strip 访问不一定更快
    适合高性能临时数据 可靠性比单盘更差

    8. 4 RAID 1¶

    RAID 1 又称 mirroring / shadowing，把同一份数据完整写到两块磁盘。

    RAID 1 的读写特性

    • 每次写入必须写到所有 mirror，因此写成本较高
    • 读取时可从 seek time 更短的那块盘读
    • 除非多个 mirror 同时失效，否则数据仍可恢复
    • 容量利用率约为 50%

    8. 5 RAID 2 and RAID 3¶

    RAID 2 在 bit-level 做 striping，并使用 Hamming code 做错误校正。课件指出它基本不使用。

    RAID 3 使用 bit-interleaved parity。数据 bit 分散到多块 data disks，另有专用 parity disk 保存所有 data disks 的 XOR parity。

    RAID 3 Parity 示例

    若 4 块数据盘保存 bits：

    0 1 1 0

    parity bit 为：

    \[ 0 \oplus 1 \oplus 1 \oplus 0 = 0 \]

    若其中一位丢失，例如：

    0 ? 1 0

    可用剩余 bits 与 parity bit 再做 XOR 恢复丢失 bit。

    RAID 3 的代价

    Bit-level striping 可提高并行性能，但每次写都要更新 parity，XOR 开销通常由硬件完成；恢复时需要大量 XOR，recovery time 较长。

    8. 6 RAID 4, RAID 5 and RAID 6¶

    Level 做法 特点
    RAID 4 block-level striping + 专用 parity disk 小读只访问一块 data disk，但 parity disk 可能成为写瓶颈
    RAID 5 类似 RAID 4，但 parity 分布到所有 disks 避免单独 parity disk 热点，是常见折中
    RAID 6 RAID 5 基础上增加第二个 parity block 可容忍更多磁盘失效，写入和容量成本更高
    组合 RAID
    • RAID 1+0 / RAID 10：先镜像再条带化，兼顾性能与恢复能力
    • RAID 5+0：把 RAID 5 arrays 再做 striping
    • RAID 6+0：把 RAID 6 arrays 再做 striping

    组合等级通常用于更大规模、更高吞吐或更高可用性的存储系统。

    8. 7 RAID and File Systems¶

    RAID 可以检测并恢复磁盘失效，但它并不能自动防止所有数据损坏。

    RAID 不能解决的错误

    • 文件系统 metadata corruption
    • 写入路径中的 silent data corruption
    • 软件 bug 导致的错误写入
    • 应用层误删、覆盖或逻辑错误

    因此一些文件系统会额外加入 checksum 和自恢复机制，例如 Solaris ZFS。

    ZFS 的思路
    • 对所有 FS data 和 metadata 加 checksum
    • Checksum 与指向 data / metadata 的 pointer 放在一起
    • 读取时可检查并发现数据或 metadata corruption
    • 若底层有冗余副本，可用正确副本修复错误

    ZFS 还使用 storage pools，而不是传统固定 volumes / partitions。

    Traditional Storage vs Pooled Storage

    传统方式先把磁盘切成 volumes / partitions，再在其上建文件系统。Pooled storage 则把 disks 放入统一 pool，pool 内多个 file systems 可共享空间，并从 pool 中动态分配和释放。

    9 Summary¶

    本章总结

    • Magnetic disk 对外通过 logical blocks 提供一维地址空间
    • 磁盘访问时间主要由 seek time、rotational latency、transfer time 和 controller overhead 构成
    • FCFS 简单公平但不优化 seek；SSTF 减少 seek 但可能 starvation；SCAN / C-SCAN / LOOK / C-LOOK 更适合连续负载
    • SSD 没有 seek 和 rotation，但有 page 写入、block 擦除、FTL、GC、over-provisioning 和 wear leveling 问题
    • Disk management 包含 formatting、partition、logical formatting、mount、boot block、bad block、raw access 和 swap space
    • Host-attached storage、NAS、SAN 分别适合不同连接方式和共享规模
    • RAID 通过 mirroring、striping、parity 改善可靠性和性能，但不能替代文件系统层的数据完整性检查
