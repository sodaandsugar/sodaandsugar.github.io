    Chapter 8 File System Interface¶

    前两章已经讨论了 mass storage 和 I/O 系统。本章开始讨论用户和程序真正使用存储时看到的抽象：file system。文件系统把底层 track、sector、block 隐藏起来，向用户提供 file、directory、path、permission 等更稳定的接口。

    本章主线

    • Storage 的核心抽象是 file
    • File system 为用户提供一组 files 的一致视图，并提供 protection
    • 文件有 attributes、operations、types 和 structures
    • 文件访问方式包括 sequential access、direct access 和 indexed access
    • Directory 用于组织 file names 到 file metadata 的映射
    • Directory structure 可从 single-level 发展到 tree、acyclic graph 和 general graph
    • Mounting 把不同 file systems 连接成统一 namespace
    • Sharing 和 protection 需要 user / group / ACL / permission bits 等机制

    1 How to Use Storage¶

    有了 disk 和 I/O 之后，还需要回答：应用到底如何使用存储？

    最原始的方式是直接使用 disk，但这要求程序理解 track、sector、block allocation、bad block、concurrent access 等大量细节，既困难也不安全。

    File System 的作用

    • File system 是 disk 的抽象
    • 用户进程看到的是 file，而不是 track / sector
    • File system 提供一组 files 的 coherent view
    • Unix 中 file 可理解为连续的 logical byte stream
    • File system 同时提供 protection
    CPU、Memory、Storage 分别抽象成什么
    • CPU 常被 OS 抽象为 process / thread
    • Memory 常被抽象为 address space
    • Storage 常被抽象为 file / file system

    这些抽象让程序不必直接管理硬件细节。

    本章主要回答两个层面的问题：

    • 如何使用 file system
      • 如何使用 file
      • 如何使用 directory
    • 如何实现 file system
      • 如何实现 file
      • 如何实现 directory

    本章侧重 interface，下一章侧重 implementation。

    2 File Concept¶

    File 是用于保存信息的一段连续 logical space。文件内容可以是 database、audio、video、web pages、program、text 等。

    File 的类型

    • Data file
      • character data
      • binary data
      • application-specific data
    • Program file
      • 可执行程序或可加载代码
    • Special file
      • 例如 proc file system 使用 file-system interface 暴露 system information

    2. 1 File Attributes¶

    文件不仅有内容，还有 metadata。

    Attribute 含义
    Name 人类可读的文件名
    Identifier 文件系统内唯一标识，如 inode number
    Type 文件类型，某些系统需要
    Location 文件在设备上的位置指针
    Size 当前文件大小
    Protection 谁能 read、write、execute
    Time / date / user identification 用于 protection、security、usage monitoring
    Extended attributes 例如 checksum、label、自定义 metadata

    文件信息保存在 directory structure 中，而 directory structure 本身也存储在磁盘上。

    2. 2 File Operations¶

    OS 提供基本 file operations，其它复杂操作通常可由这些基本操作组合出来。

    常见 File Operations
    • create
      • 在 file system 中找到空间
      • 在 directory 中分配一个 entry
    • open
      • 多数操作前需要先 open
      • 返回 handler / file descriptor，供后续操作使用
    • read / write
      • 需要维护当前 file pointer
    • reposition / seek
      • 改变当前读写位置
    • close
      • 释放本进程打开文件的相关状态
    • delete
      • 释放文件占用空间
      • 对 hardlink，需要维护 link count，最后一个 link 删除后才真正删除文件
    • truncate
      • 清空文件内容，但保留 attributes
    Copying 如何实现

    Copying 不是必须由文件系统作为原语直接提供。可以通过：

    1. create 目标文件
    2. open 源文件和目标文件
    3. 循环 read 源文件、write 目标文件
    4. close 两个文件

    2. 3 Open Files¶

    打开文件后，OS 需要维护额外状态。

    数据 说明
    Open-file table 跟踪系统中打开的文件
    File pointer 当前读写位置，对每个打开该文件的进程分别维护
    File-open count 文件被打开的次数，最后一次 close 后才能移除 open-file table 项
    Disk location of file 缓存文件位置相关信息，减少重复查找
    Access rights 本次 open 的访问模式，如 read-only、write-only、read-write

    为什么 open 很重要

    如果每次 read / write 都从路径名重新查目录、查权限、查磁盘位置，开销会很高。open 把这些查找结果缓存成一个 handle，后续操作直接使用该 handle。

    2. 4 File Locks¶

    某些文件系统提供 file lock，用于协调多个进程对同一文件的访问。

    锁类型 含义
    Shared lock 多个进程可同时持有，常用于读共享
    Exclusive lock 一次只能一个进程持有，常用于写独占
    锁机制 含义
    Mandatory lock OS 根据锁状态强制拒绝不允许的访问
    Advisory lock OS 提供锁状态，进程自愿遵守并决定如何处理

    2. 5 File Types¶

    OS 和应用可以通过多种方式识别文件类型。

    识别 File Type 的方式
    • 作为文件名的一部分，例如 file extension：.c、.txt、.jpg
    • 通过 magic number 判断，例如 ELF 可执行文件头
    • 通过文件系统 metadata 或 application-specific metadata 判断

    2. 6 File Structure¶

    文件可以有不同结构，具体由 OS 或应用决定。

    结构 含义 示例
    No structure byte stream / word stream Linux / Unix 常见模型
    Simple record structure 固定或可变长度 records 数据库、记录文件
    Complex structure 复杂内部格式 Word document、relocatable object file

    Unix 风格

    Unix / Linux 通常把文件视作 byte stream。文件系统不理解 Word 文档、数据库页、图片格式等语义，这些结构由 user programs 自己解释。

    3 Access Methods¶

    文件系统需要支持不同访问模式。

    3. 1 Sequential Access¶

    Sequential access 按预定顺序访问文件元素。磁带这类介质天然适合顺序访问。

    Sequential Access 的典型操作
    • read next
    • write next
    • 自动推进 current file pointer
    • 可 rewind 回到开头

    3. 2 Direct Access¶

    Direct access 允许在序列中任意位置访问元素，访问时间大致与文件大小无关，也常称 random access。

    Direct Access 的意义

    Direct access 适合数据库、索引文件、大型二进制文件等场景。程序可以直接访问第 n 个 block / record，而不必从文件开头顺序扫描。

    Tape 上也能模拟 random access 吗

    可以，但代价不稳定。磁带需要 wind / rewind 到目标位置，因此访问时间强烈依赖当前位置和目标位置，不是真正意义上的 roughly equal time direct access。

    3. 3 Indexed Access¶

    其它访问方法常建立在 direct access 上。例如给文件建立 index，index 指向文件中的 blocks。

    Indexed Access
    • 先搜索 index，找到目标 record 所在 block
    • 再用 pointer 直接访问该 block
    • index 可以有多层，以支持更大文件或更快查找

    4 Disk and File System¶

    一个 disk 可以被划分成多个 partitions。不同 partitions 可以使用不同 file systems。

    概念 含义
    Partition 磁盘上的一个逻辑分区，也称 minidisk / slice
    Volume 包含 file system 的 partition
    Table of contents 每个 volume 跟踪本文件系统信息的数据结构
    Raw disk 不使用 file system，应用直接管理 blocks

    Raw Disk 的典型使用者

    数据库系统有时更愿意直接管理磁盘块、缓存、日志和一致性，避免 OS file system 的额外策略干扰。

    5 Directory Structure¶

    Directory 是一组 nodes 的集合，每个 node 包含某个文件的信息。Directory structure 和 file contents 都存放在磁盘上。

    5. 1 Operations on Directory¶

    常见 directory operations 包括：

    • Create a file：新文件需要加入 directory
    • Delete a file：从 directory 中移除文件
    • List a directory：列出目录中所有文件
    • Search for a file：按名字或 pattern 查找
    • Traverse the file system：递归访问目录下每个文件和子目录

    5. 2 Directory Organization Goals¶

    Directory organization 需要兼顾：

    目标 含义
    Efficiency 快速定位文件
    Naming 提供用户方便理解的命名结构
    Grouping 支持按项目、用户、类型等方式组织文件
    Sharing 支持同一文件有多个名字或被多个用户访问

    6 Directory Organizations¶

    6. 1 Single-Level Directory¶

    Single-level directory 为所有用户维护一个全局 directory。

    Single-Level Directory 的问题

    • 所有文件位于同一目录，命名冲突严重
    • 两个用户不能方便地使用相同 file name 表示不同文件
    • 难以分组管理
    • 文件数量大时搜索和浏览都不方便

    6. 2 Two-Level Directory¶

    Two-level directory 为每个用户提供独立的 UFD（User File Directory），所有 UFD 由 MFD（Master File Directory） 管理。

    Two-Level Directory 的改进

    • 不同用户可以拥有同名文件
    • 搜索效率比 single-level 更好
    • 用户文件彼此隔离
    Two-Level Directory 的新问题

    如何在不同用户之间共享文件？这需要引入 path concept、link 或更复杂的 directory graph。

    6. 3 Tree-Structured Directories¶

    Tree-structured directory 把文件组织成树，是现代 OS 中最常见的基本模型。

    概念 示例
    Absolute path name /home/alice/file.txt
    Relative path name 相对于 current directory，例如 ../tmp/a
    Current directory pwd 所显示的目录
    创建文件和目录
    • 创建新文件：touch <file-name>
    • 删除文件：rm <file-name>
    • 创建子目录：mkdir <dir-name>

    若当前目录是 /mail，执行：

    mkdir count

    会创建 /mail/count。

    Tree 中的共享限制

    严格 tree structure 不允许一个文件或目录同时有多个父目录。因此如果要共享同一个文件 / 目录，需要突破 tree，进入 graph structure。

    删除非空目录

    删除 directory 时有两种策略：

    • Option I：只有空目录才能删除
    • Option II：递归删除目录下所有 files、directories 和 sub-directories

    sudo rm -rf / 是递归删除根目录的危险例子，真实系统通常会有额外保护。

    6. 4 Acyclic-Graph Directories¶

    Acyclic-graph directory 允许通过 links 共享文件或目录，但不允许形成 cycle。

    为什么需要 Acyclic Graph

    它允许 aliasing：同一个文件可以通过不同路径被访问，不再局限于唯一父目录。

    Dangling Pointer Problem

    若某个文件被多个 directory entries 指向，其中一个路径删除了文件实体，其它路径就可能变成 dangling pointer。

    解决思路：

    • Back pointers：记录所有指向该实体的 pointers，但记录长度可变
    • Reference counter / link count：记录 link 数，只有计数为 0 时才真正删除实体

    Hard Link and Soft Link¶

    Link 含义 特点
    Hard link 多个 directory entries 指向同一个文件实体 / inode 依赖 reference count
    Soft link / symbolic link 一个特殊文件保存目标路径名 目标删除后可能 dangling

    6. 5 General Graph Directory¶

    General graph directory 允许任意 links，因此可能形成 cycles。

    Cycle 带来的问题

    • 遍历目录时可能无限循环
    • 删除后空间回收更复杂
    • reference count 无法简单判断不可达对象，因为 cycle 中对象可能互相引用
    处理 Cycle 的方法
    • 允许 cycle，但使用 garbage collection 回收不可达 disk space
    • 每次新增 link 时运行 cycle detection algorithm，阻止形成 cycle

    7 File System Mounting¶

    一个 file system 必须先 mount，才能被访问。Mounting 把一个文件系统连接到当前系统 namespace 中，通常形成单一目录树。

    概念 含义
    Mount point 被挂载文件系统接入的位置
    Mounted file system 已接入 namespace 的文件系统
    Hidden old directory mount point 原有目录内容在挂载期间被遮蔽

    Mount 的效果

    若把某个 partition mount 到 /users，则访问 /users 时看到的是该 partition 的 root，而不是原来 root file system 中 /users 目录下的旧内容。

    8 File Sharing¶

    多用户系统中，file sharing 很有用，但必须配合 protection scheme。

    本地多用户共享
    • User ID 标识用户，使 protection 可按 user 设置
    • Group ID 把用户组织成组，使 group access rights 成为可能

    分布式系统中，文件可通过网络共享，典型方法是 NFS（Network File System）。

    8. 1 Remote File Sharing¶

    Remote file sharing 使用网络让不同系统之间访问文件。

    方式 特点
    FTP 等手动程序 用户显式上传 / 下载
    Distributed file systems 自动、透明地把远程 FS 接入本地 namespace
    World Wide Web 半自动共享和访问内容

    Client-Server Model

    • Server 可服务多个 clients
    • Client 可 mount server 上的 remote file system
    • 标准 OS file calls 会被转换成 remote calls
    • Client 和 client 上 user 的身份识别较复杂
    • Server 不能简单假设 client 可信

    常见协议包括：

    • NFS：标准 UNIX file sharing protocol
    • CIFS / SMB：Windows 常见 file sharing protocol

    9 Protection¶

    File owner / creator 应能控制：

    • what can be done
    • by whom

    9. 1 Types of Access¶

    文件系统常见访问类型包括：

    • read
    • write
    • append
    • execute
    • delete
    • list

    9. 2 Access Control List¶

    ACL（Access Control List）为每个 file / directory 维护访问控制列表。

    优点 缺点
    控制粒度细 如何构造 list 复杂
    可精确指定不同用户 / 组权限 如何在 directory / metadata 中高效存储 list 复杂

    9. 3 Unix Access Control¶

    Unix 传统权限模型使用三类用户和三种权限。

    用户类别 含义
    owner 文件所有者
    group 文件所属组
    others 其他用户
    权限 含义 bit
    read 读文件或列目录 r
    write 写文件或修改目录 w
    execute 执行文件或进入目录 x
    761 权限

    课件示例：

    类别 数字 二进制 权限
    owner 7 111 rwx
    group 6 110 rw-
    others 1 001 --x

    在 Linux 中可用 chmod 修改权限，用 chgrp 修改所属组。

    Unix 权限的简洁性

    Unix 模型比 ACL 粗粒度，但非常紧凑、容易检查、容易缓存。实际系统常同时支持传统 mode bits 和更细粒度 ACL。

    10 Summary¶

    本章总结

    • File system 把 disk 抽象成 file 和 directory，并提供 protection
    • File attributes 包括 name、identifier、type、location、size、protection、time/date/user 等
    • File operations 包括 create、open、read/write、seek、close、delete、truncate
    • Open-file table、file pointer、open count、access rights 是管理 open files 的核心状态
    • File structure 可以是 byte stream、record structure 或 application-specific complex structure
    • Access methods 包括 sequential、direct 和 indexed
    • Directory organization 从 single-level 到 two-level、tree、acyclic graph、general graph 逐步增强共享能力
    • Mounting 把多个 file systems 接入统一 namespace
    • File sharing 需要 user ID、group ID、NFS / CIFS 等机制
    • Protection 可通过 ACL 或 Unix rwx mode bits 实现
