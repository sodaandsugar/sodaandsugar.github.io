    Chapter 15 Miscellaneous Points¶

    1 Named Casts¶

    为什么不用 C 风格强转

    • C 风格 cast 含义过于宽泛
    • 容易做出危险转换
    • 也不方便搜索和维护

    优先使用命名转换

    • static_cast
    • dynamic_cast
    • reinterpret_cast
    • const_cast

    1.1 static_cast¶

    Example

    double d = 7.1;
int a;

a = d;                    // implicit
a = (int)d;               // C-style
a = static_cast<int>(d);  // 更明确

    Tip

    • 适合语义上合理、编译器可检查的转换

    1.2 reinterpret_cast¶

    Example

    int a = 7;
double* p;

p = (double*)&a;                    // C-style
// p = static_cast<double*>(&a);    // error
p = reinterpret_cast<double*>(&a);  // 强行按位解释
    Tip
    • 这是最危险的一类转换之一
    • 仅当你真的明确知道自己在做什么时才用

    1.3 const_cast¶

    Example

    const int c = 7;
int* q;

// q = &c;                    // error
q = const_cast<int*>(&c);
    Tip
    • 用于增加/去除顶层 const
    • 即使能去掉 const，也不代表修改原对象一定合法

    1.4 dynamic_cast¶

    运行时向下转型

    struct A { virtual void f() {} };
struct B : public A {};
struct C : public A {};

A* pa = new B;
C* pc1 = static_cast<C*>(pa);   // 编译可过，但不安全
C* pc2 = dynamic_cast<C*>(pa);  // 运行时失败，得到 nullptr

    Tip

    • dynamic_cast 依赖运行时类型信息（RTTI）
    • 基类必须是多态类型，通常意味着至少有一个虚函数
    • 指针转换失败返回 nullptr，引用转换失败会抛出异常

    2 Multiple Inheritance¶

    多重继承

    • 一个类可以同时继承多个基类
    • 例如 Consultant 同时继承 MTS 和 Temporary

    Example

    class Employee {
protected:
    String name;
    EmpID id;
};

class MTS : public Employee {
protected:
    Degrees degree_info;
};

class Temporary {
protected:
    Company employer;
};

class Consultant : public MTS, public Temporary {
    // ...
};

    Tip
    • Consultant 会同时拿到：
      • name
      • id
      • degree_info
      • employer

    3 Problems of Vanilla MI¶

    普通多继承的典型问题

    • 数据布局复杂
    • 可能复制出多份基类子对象
    • 名称与转换可能变得二义
    普通多继承会让对象布局变复杂

    Consultant 同时含有 MTS 和 Temporary 两个基类子对象；如果这些基类链上再共享同一个祖先类，就可能出现重复祖先子对象。

    重复基类

    struct B1 { int m_i; };
struct D1 : public B1 {};
struct D2 : public B1 {};
struct M : public D1, public D2 {};

M m;
// B1* p = &m; // ERROR: 哪一个 B1?
B1* p1 = static_cast<D1*>(&m);
B1* p2 = static_cast<D2*>(&m);

    数据成员歧义

    M m;
// m.m_i++; // ERROR: D1::B1::m_i 还是 D2::B1::m_i ?
    何时复制基类无伤大雅
    • 若基类只是纯接口类、不含数据状态，复制通常问题不大

    4 Safe Uses of MI¶

    较安全的用途

    • 组合多个协议/接口类（protocol / interface classes）

    接口类

    class CDevice {
public:
    virtual ~CDevice() {}
    virtual int read(...) = 0;
    virtual int write(...) = 0;
    virtual int open(...) = 0;
    virtual int close(...) = 0;
    virtual int ioctl(...) = 0;
};

    5 Virtual Base Classes¶

    虚基类

    • 为避免重复基类，可把基类声明为 virtual
    • 在 C++ 语境里，virtual 往往意味着“间接访问”

    Example

    struct B1 { int m_i; };
struct D1 : virtual public B1 {};
struct D2 : virtual public B1 {};
struct M : public D1, public D2 {};

int main() {
    M m;
    m.m_i++;      // OK，只剩一份 B1
    B1* p = new M; // OK
}
    虚基类的代价
    • 运行时和空间上都有额外开销
    • 构造顺序与责任更复杂
    • 名字冲突与支配规则（dominance rule）更难理解
    iostream 中共享基类的图示

    虚基类可以让最底层派生类只保留一份虚基类子对象。代价是实现会通过间接指针访问虚基类部分，因此空间与运行期复杂度都会上升。

    结论

    • 多重继承应谨慎使用
    • 尤其避免菱形继承
    • 若只是组合多个接口，优先考虑“接口类 + 受控多继承”的写法

    6 Namespaces¶

    为什么要命名空间

    • 避免全局名字冲突
    • 表达逻辑分组
    • 它本身就是一种作用域

    旧头文件冲突

    // old1.h
void f();
void g();

// old2.h
void f();
void g();

    用 namespace 包装

    namespace old1 {
    void f();
    void g();
}

namespace old2 {
    void f();
    void g();
}

    7 Defining and Implementing Namespaces¶

    定义

    namespace MyLib {
    void foo();
    class Cat {
    public:
        void Meow();
    };
}

    实现

    void MyLib::foo() {
    cout << "foo\n";
}

void MyLib::Cat::Meow() {
    cout << "meow\n";
}

    8 Using Names from a Namespace¶

    显式限定

    MyLib::foo();
MyLib::Cat c;
c.Meow();

    using 声明

    • 只引入指定名字

    Example

    using MyLib::foo;
using MyLib::Cat;

foo();
Cat c;
c.Meow();

    using namespace 指令

    • 把整个命名空间中的名字都引入可见范围

    Example

    using namespace std;
using namespace MyLib;

foo();
Cat c;
cout << "hello" << endl;
    Tip
    • using namespace 方便，但可能引入二义性

    9 Ambiguities and Resolution¶

    Example

    namespace XLib {
    void x();
    void y();
}

namespace YLib {
    void y();
    void z();
}

using namespace XLib;
using namespace YLib;

x();       // OK
// y();    // Error: ambiguous
XLib::y(); // OK
z();       // OK

    10 Namespace Aliases and Composition¶

    命名空间别名

    namespace supercalifragilistic {
    void f();
}

namespace short_ns = supercalifragilistic;
short_ns::f();

    命名空间组合

    • 可以把其他命名空间中的名字重新组织到新命名空间中

    Example

    namespace first {
    void x();
    void y();
}

namespace second {
    void y();
    void z();
}

namespace mine {
    using namespace first;
    using namespace second;
    using first::y; // 解决冲突
    void mystuff();
}

    11 Namespace Selection and Open Namespaces¶

    选择性导入

    namespace mine {
    using orig::Cat;
    void x();
    void y();
}
    • 只拿自己需要的名字，而不是整包导入

    命名空间是开放的

    • 同一个命名空间可以分散定义在多个文件中

    Example

    // header1.h
namespace X {
    void f();
}

// header2.h
namespace X {
    void g();
}
    • 最终 X 同时拥有 f() 和 g()
