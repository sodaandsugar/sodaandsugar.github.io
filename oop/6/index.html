    Chapter 6 Polymorphism¶

    1 Basic Idea¶

    多态（Polymorphism）
    • 允许把派生类对象当作基类对象来使用
    • 真正调用哪个成员函数，在运行期根据对象的实际类型决定

    图形程序的抽象层次

    • Shape：公共属性如 center，公共操作如 move()、render()、resize()
    • Ellipse、Circle、Rectangle：在公共接口上实现各自行为
    设计提醒
    • 课件中特别说明：Circle 从 Ellipse 继承在概念上未必是最佳设计

    2 Virtual Functions and Dynamic Binding¶

    基类 Shape

    class Point { /* ... */ };

class Shape {
public:
    Shape();
    void move(const Point&);
    virtual void render();
    virtual void resize();
    virtual ~Shape();
protected:
    Point center;
};

    派生类

    class Ellipse : public Shape {
public:
    Ellipse(float major, float minor);
    virtual void render();
protected:
    float major_axis, minor_axis;
};

class Circle : public Ellipse {
public:
    Circle(float radius) : Ellipse(radius, radius) {}
    virtual void render();
};

    通过基类指针调用

    void render(Shape* p) {
    p->render(); // 调用与实际对象类型匹配的 render()
}

void func() {
    Ellipse ell(10, 20);
    Circle circ(40);

    ell.render();
    circ.render();
    render(&ell);
    render(&circ);
}
    静态绑定 vs 动态绑定
    • Static binding：按变量的声明类型决定调用哪个函数
    • Dynamic binding：按对象的真实类型决定调用哪个函数
    • virtual 开启动态绑定

    3 How Virtual Works¶

    实现机制

    • 含虚函数的对象通常含有一个隐藏指针 vptr
    • vptr 指向该类的虚函数表（vtable）
    • 调用虚函数时，运行期通过 vptr 找到正确版本
    结果
    • Shape、Ellipse、Circle 各自有不同的 vtable
    • 同名虚函数在不同派生类中可以对应不同实现

    4 Object Slicing¶

    对象赋值会发生切片

    Ellipse elly(20F, 40F);
Circle circ(60F);
elly = circ;
    发生了什么
    • Circle 中超出 Ellipse 的那部分数据会被切掉（slice off）
    • 例如 Circle 特有的 area 不会复制到 elly
    • elly 自己的 vptr 仍指向 Ellipse 的 vtable

    结果

    (&elly)->render(); // Ellipse::render()

    5 Pointers and References Preserve Polymorphism¶

    指针情况

    Ellipse* elly = new Ellipse(20F, 40F);
Circle* circ = new Circle(60F);
elly = circ;

elly->render(); // Circle::render()
    注意
    • 原来 elly 指向的 Ellipse 对象会丢失，造成内存泄漏
    • 但多态本身仍然成立，因为 elly 和 circ 现在都指向同一个 Circle

    引用情况

    void func(Ellipse& elly) {
    elly.render();
}

Circle circ(60F);
func(circ); // 调用 Circle::render()
    结论
    • 引用和指针一样，也能保留动态绑定

    6 Virtual Destructors¶

    析构函数应设为 virtual 的场景

    • 如果一个类可能被继承，并且你会通过基类指针删除对象，基类析构函数必须是 virtual

    Example

    Shape* p = new Ellipse(100.0F, 200.0F);
delete p;
    如果不是 virtual
    • 只会调用 Shape::~Shape()
    • Ellipse::~Ellipse() 不会执行，资源释放不完整

    7 Overriding¶

    覆盖（Overriding）

    • 派生类重新定义虚函数函数体
    • 现代 C++ 推荐使用 override 明确表达“这是在覆盖基类版本”

    Example

    class Base {
public:
    virtual void func();
};

class Derived : public Base {
public:
    void func() override;
};

    复用基类逻辑

    void Derived::func() {
    cout << "In Derived::func!";
    Base::func(); // 调用基类版本
}

    8 Covariant Return Types¶

    返回类型放宽（covariant return type）

    • 若 D 公有继承自 B
    • 则 D::f() 可以把返回类型从 B* / B& 收窄为 D* / D&
    • 仅适用于指针和引用

    Example

    class Expr {
public:
    virtual Expr* newExpr();
    virtual Expr& clone();
    virtual Expr self();
};

class BinaryExpr : public Expr {
public:
    virtual BinaryExpr* newExpr(); // ok
    virtual BinaryExpr& clone();   // ok
    virtual BinaryExpr self();     // Error
};

    9 Overloading and Virtual¶

    重载与覆盖的关系

    • 基类中若有一组重载虚函数，派生类若覆盖其中一个，同名其他重载也会被隐藏
    • 实践上应把整组重载都补齐

    Example

    class Base {
public:
    virtual void func();
    virtual void func(int);
};

class Derived : public Base {
public:
    virtual void func() {
        Base::func();
    }
    virtual void func(int) { /* ... */ }
};

    10 Design Tips¶

    多态相关建议
    • 不要重新定义继承来的非虚函数
      • 非虚函数是静态绑定，没有动态分派
    • 不要重新定义继承来的默认参数值
      • 默认参数也是静态绑定

    11 Abstract Classes and Interface Classes¶

    抽象类的作用

    • 用于建模
    • 强制派生类遵守接口
    • 定义接口而不提供完整实现

    适用场景

    • 当前信息不足，无法给出通用实现
    • 只想提供接口继承
    Protocol / Interface Class
    • 典型接口类特点：
      • 除析构函数外，所有非静态成员函数均为纯虚函数
      • 析构函数是虚函数，且通常为空实现
      • 不含非静态数据成员
      • 可以含静态成员

    接口类示例

    class CDevice {
public:
    virtual ~CDevice() {}

    virtual int read(...) = 0;
    virtual int write(...) = 0;
    virtual int open(...) = 0;
    virtual int close(...) = 0;
    virtual int ioctl(...) = 0;
};
