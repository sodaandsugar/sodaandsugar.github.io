    Chapter 2 Regulations¶

    本章范围

    本章对应课件中的 Introduction to Computer Networks: Regulations，课件最后标注教学内容对应 Chapter 1.5-1.11，主要讨论：

    • Network protocols：网络协议如何被设计、分层和实现。
    • Reference models：OSI、TCP/IP 与五层混合模型。
    • Standardization：标准如何形成，以及 ITU、ISO、IEEE、IETF 等组织的作用。
    • Policies：网络中与法律、社会和政策相关的问题。
    • Metrics：网络中常用的容量与速率单位。

    1 Design Goals¶

    网络协议通常围绕四类设计目标展开：reliability、resource allocation、evolvability、security。

    目标 含义 典型机制
    Reliability 从错误、故障或失效中恢复 Error detection / correction codes、routing
    Resource allocation 共享有限的公共资源 Statistical multiplexing、flow control、congestion control、QoS
    Evolvability 支持协议和网络结构逐步演进 Protocol layering、addressing / naming、internetworking
    Security 防御各种网络攻击 Confidentiality、authentication、integrity

    1. 1 Reliability¶

    可靠性（Reliability）指网络在部分组件不可靠时仍能正确运行的能力。网络中的比特可能因为电噪声、无线干扰、硬件缺陷或软件错误而被破坏，因此协议需要发现并修复错误。

    • Error detection：在数据中加入冗余信息，用于发现接收端收到的数据是否出错。
    • Error correction：通过更强的冗余编码，使接收端可以直接恢复正确数据。
    • Retransmission：发现错误后重传，直到数据被正确接收。
    • Routing：当某些链路或路由器损坏时，自动为数据选择其他可用路径。
    Routing 也是可靠性的组成部分

    如果 London 到 Rome 的原路径经过 Berlin，而 Berlin 的网络故障，网络应能自动选择例如经 Paris 的替代路径。这个问题属于 routing。

    1. 2 Resource Allocation¶

    资源分配（Resource Allocation）关注多个用户或应用如何共享共同且有限的网络资源，例如带宽、缓存和处理能力。

    Scalability

    Scalable design 指网络变大后仍能良好工作的设计。资源分配机制必须能随网络规模增长而继续有效。

    • Statistical multiplexing（统计复用）：根据需求的统计特征动态共享带宽，而不是为每个用户长期固定预留资源。
    • Flow control（流量控制）：接收方向发送方反馈自身接收能力，使发送方调整发送速率，避免压垮接收端。
    • Congestion control（拥塞控制）：当网络出现拥塞，即网络过载时，要求计算机降低资源需求，例如减少带宽占用。
    • Quality of Service, QoS（服务质量）：通过机制协调相互竞争的需求，例如实时视频希望低延迟，批量传输希望高吞吐量。
    实时性与吞吐量的冲突

    实时视频更重视按时到达，即使个别数据丢失也可能可接受；大文件传输更重视完整性和高吞吐量。QoS 的任务是协调这类不同应用的需求。

    1. 3 Evolvability¶

    可演进性（Evolvability）指协议可以随时间逐步改进，并能把新设计连接到既有网络中。

    • Protocol layering（协议分层）：把整体问题拆成多个层次，并隐藏每层内部实现细节，使某一层可以在不破坏其他层的情况下演进。
    • Addressing / naming（寻址 / 命名）：每一层都需要识别某条消息涉及的发送方和接收方。低层更常称 addressing，高层更常称 naming。
    • Internetworking（互连网络）：不同网络技术可能有不同限制，例如是否保持消息顺序、最大消息大小是否相同，因此需要编号、拆分、传输和重组等机制。

    1. 4 Security¶

    安全性（Security）关注网络如何防御各种攻击。

    机制 作用
    Confidentiality（机密性） 防止通信内容被窃听
    Authentication（认证） 防止攻击者冒充他人
    Integrity（完整性） 防止消息被暗中篡改
    安全机制的例子
    • 认证可以用于区分真实银行网站与伪造网站。
    • 移动网络可以通过认证确认某个电话确实来自用户手机。
    • 完整性机制可以防止消息从 “debit my account $10” 被篡改为 “debit my account $1000”。

    2 Protocol Layering¶

    2. 1 Layering and Protocol¶

    为降低设计复杂度，大多数网络被组织为一组 layers / levels（层次）。每一层建立在下一层之上，为更高层提供服务，同时隐藏服务内部如何实现。

    基本概念
    • Protocol（协议）：通信双方关于通信如何进行的一组约定。
    • Layer n protocol（第 n 层协议）：两台机器上的第 n 层实体之间交谈时使用的规则和约定。
    • Peer（对等实体）：不同机器上处于对应层次的实体，可以是软件进程、硬件设备，甚至是人。
    • Interface（接口）：相邻两层之间的边界，定义下层向上层提供哪些 primitive operations 和 services。

    类比

    五层网络模型可以类比计算机体系结构中的 five-stage pipeline：每一级只处理自己的职责，并通过清晰边界与相邻级协作。

    2. 2 Virtual and Actual Communication¶

    第 \(n\) 层的两个 peer 从概念上看像是在直接通信，这称为 virtual communication（虚拟通信）。但实际上，第 \(n\) 层的数据会交给第 \(n-1\) 层，再逐层向下，直到物理介质。

    • Virtual communication：同层 peer 之间的逻辑通信。
    • Actual communication：数据真正经过低层和物理介质传输。
    • 第 \(n\) 层的 peer 不会直接把数据发给对端第 \(n\) 层，而是依赖下层逐层传递。

    Clean interface

    清晰的层间接口可以降低层间依赖，使某一层协议或实现被替换时，上下层不必感知内部变化。例如把电话线替换为卫星链路，只要对上层提供相同服务，上层协议无需改变。

    2. 3 Network Architecture and Protocol Stack¶

    • Network architecture（网络体系结构）：一组 layers 和 protocols。
    • Protocol stack（协议栈）：某个系统使用的协议列表，每层一个协议。

    网络体系结构需要给实现者足够信息，使其能够为每层编写程序或构建硬件，并正确遵守协议。但实现细节和机器内部接口通常不是体系结构的一部分，因为它们从外部不可见。

    Architecture 不等于 implementation

    不同主机可以用不同实现运行同一协议，只要它们能正确使用同一组协议即可。协议本身也可以变化，只要对相邻层暴露的服务不变。

    2. 4 Layering Analogy¶

    Philosopher-Translator-Secretary Architecture

    两位哲学家没有共同语言，因此各自通过 translator 和 secretary 通信：

    • 哲学家是 layer 3 peers。
    • 翻译是 layer 2 peers，约定使用某种中间语言。
    • 秘书是 layer 1 peers，使用传真、电话或邮件等底层方式传输。
    • 每层只需维持对上下层的接口，内部协议可以独立替换。

    2. 5 Encapsulation and Fragmentation¶

    在更技术化的例子中，应用层产生消息 \(M\)，逐层向下传输：

    • 上层消息传给下层后，下层通常会添加自己的 header（首部）。
    • 某些层还会添加 trailer（尾部），例如用于错误检测的 checksum。
    • Header 中可能包含地址、sequence number、大小、时间等控制信息。
    • 如果下层协议对最大消息大小有限制，消息可能被拆成多个更小的 packet（分组）。
    • 接收端逐层向上交付时，各层会剥离属于自己的 header / trailer。
    Header, payload, trailer
    • Header：控制信息，例如源地址、目的地址、序号。
    • Payload：真正要传输的数据。
    • Trailer：尾部控制信息，常见用途是错误检测。

    3 Services and Protocols¶

    3. 1 Connection-Oriented Service¶

    Connection-oriented service（面向连接服务）以电话系统为模型：先建立连接，再使用连接，最后释放连接。

    • 服务用户先建立连接。
    • 连接建立后，发送方、接收方和子网可以协商参数，例如最大消息大小和所需 QoS。
    • 连接像一根管道：发送方从一端放入 bit，接收方从另一端取出 bit。
    • 多数情况下，连接会保持发送顺序。
    • Circuit（电路）可以看作带有关联资源的连接，例如固定带宽。

    3. 2 Connectionless Service¶

    Connectionless service（无连接服务）以邮政系统为模型：每条消息携带完整目的地址，并被独立路由。

    • 每条消息独立处理，不依赖此前或之后的消息。
    • 同一目的地的消息通常先发先到，但不保证一定如此。
    • Packet 是网络层中的 message。
    • Datagram service（数据报服务）通常指不可靠、无确认的无连接服务。
    交换方式 含义
    Store-and-forward switching 中间节点完整接收消息后，再转发给下一跳
    Cut-through switching 中间节点尚未完整接收消息时，就开始向下一跳转发

    3. 3 Reliability of Services¶

    连接型和无连接型服务都可以具有不同可靠性。可靠服务通常通过接收端发送 acknowledgement（确认）实现。

    服务形式 特点 例子或适用场景
    Reliable connection-oriented service 不丢数据，通常保持顺序 文件传输
    Message sequences 保留消息边界 两个 1024-byte 消息仍作为两个消息到达
    Byte streams 只提供字节流，不保留消息边界 下载电影
    Acknowledged datagram 无需先建立连接，但每条数据报需要确认 类似挂号信，移动电话短信可作为例子
    Unreliable datagram 不确认、不保证送达 适合对可靠性要求低或由应用自行处理的场景

    3. 4 Service Primitives¶

    Service primitives（服务原语）是服务提供给用户进程访问该服务的一组操作。Primitive 可以要求服务执行某个动作，也可以报告 peer entity 已发生的动作。

    如果协议栈位于操作系统内，service primitives 通常表现为 system calls（系统调用），调用后进入内核态，由操作系统发送必要的数据包。

    Primitive 作用
    LISTEN 服务器声明自己准备接受连接，通常是 blocking system call
    CONNECT 客户端请求与服务器建立连接
    ACCEPT 服务器接受连接请求
    RECEIVE 准备接收请求或回复，通常会阻塞等待
    SEND 发送请求或回复
    DISCONNECT 释放连接

    Connection-oriented service 的一次交互

    1. Server 执行 LISTEN，等待连接请求。
    2. Client 执行 CONNECT，向 server 发起连接。
    3. Server 被唤醒后执行 ACCEPT，连接建立。
    4. Server 执行 RECEIVE 等待请求。
    5. Client 执行 SEND 发送请求，再执行 RECEIVE 等待回复。
    6. Server 收到请求后处理，并用 SEND 返回结果。
    7. Client 完成后执行 DISCONNECT，Server 确认并释放连接。
    Blocking system call

    Blocking system call 会使调用进程或线程暂停执行，直到请求的操作完成。例如 server 执行 LISTEN 后，会阻塞等待连接请求到来。

    3. 5 Service vs Protocol¶

    服务和协议是两个不同概念。

    概念 关注点 位置
    Service 某一层向上一层提供哪些 primitives / operations 相邻层之间的 interface
    Protocol Peer entities 之间交换的 packets / messages 的格式和含义 不同机器上的同层实体之间

    不要混淆 service 和 protocol

    Service 描述“能为上层做什么”，不描述“如何实现”。Protocol 描述 peer entities 之间如何交换数据来实现这些 service。只要暴露给上层的 service 不变，底层 protocol 可以替换。

    4 Reference Models¶

    4. 1 OSI Reference Model¶

    OSI（Open Systems Interconnection）Reference Model由 ISO 提出，把网络功能划分为七层。虽然今天几乎没有实际运行的 OSI 网络，但它定义的术语仍被广泛使用。

    OSI 层次 主要功能 常见数据单位或说明
    Application layer 为应用提供网络服务 HTTP 等应用层协议
    Presentation layer 规范 peers 之间交换数据的格式 整数长度、字节序、视频格式等
    Session layer 提供命名空间，把属于同一应用的不同 transport streams 关联起来 例如把音频流和视频流组合为同一会议
    Transport layer 实现进程到进程的通信信道 Message
    Network layer 在 packet-switched network 中处理路由 Packet
    Data link layer 把 bit stream 收集为 frame Frame
    Physical layer 在通信链路上传输原始 bit Raw bits
    • 底部三层通常运行在所有网络节点上，包括 switches / routers 和 hosts。
    • Transport layer 及以上通常只运行在 end hosts 上。
    • Data link layer 常由网卡和操作系统中的设备驱动共同实现。

    4. 2 TCP/IP Reference Model¶

    TCP/IP（Transmission Control Protocol / Internet Protocol）Reference Model源于 Internet 的实际协议族。它的强项是协议已经广泛部署。

    ① Link layer¶

    TCP/IP 模型中的 link layer 更像 hosts 与 transmission links 之间的接口。它描述串行线、Ethernet 等链路需要做什么，才能支撑无连接的 Internet layer。

    ② Internet layer¶

    Internet layer 是 TCP/IP 体系结构的核心。它允许 hosts 把 packets 注入任意网络，并让这些 packets 独立地到达目的地，即使目的地位于另一个网络中。

    • Packets 可能乱序到达，若需要按序交付，由更高层处理。
    • IP（Internet Protocol）定义正式的 packet format 和 protocol。
    • ICMP（Internet Control Message Protocol）辅助 IP 工作。
    • 主要问题包括 packet routing 和 congestion management。

    ③ Transport layer¶

    Transport layer 允许源主机和目的主机上的 peer entities 进行端到端通信。

    协议 类型 特点
    TCP（Transmission Control Protocol） 可靠、面向连接、端到端传输协议 提供无差错 byte stream；把输入字节流分段交给 Internet layer；接收端重组；负责 flow control
    UDP（User Datagram Protocol） 不可靠、无连接、端到端传输协议 不提供 TCP 的 sequencing 和 flow control；适合一次性 request-reply 查询，以及语音、视频等更重视及时到达的应用

    ④ Application layer¶

    TCP/IP 模型没有独立的 session layer 和 presentation layer。应用如果需要这些功能，通常自行包含。

    早期应用层协议包括：

    • TELNET：virtual terminal。
    • FTP（File Transfer Protocol）：文件传输。
    • SMTP（Simple Mail Transfer Protocol）：电子邮件。

    常见应用层或相关协议还包括：

    缩写 全称 作用
    DNS Domain Name System 把 host names 映射到 network addresses
    HTTP Hypertext Transfer Protocol Web 浏览器获取网页
    RTP Real-time Transport Protocol 传输语音、电影等实时媒体
    ICMP Internet Control Message Protocol 辅助 IP 工作
    DSL Digital Subscriber Line 数字用户线路
    SONET Synchronous Optical Networking 同步光网络

    4. 3 Five-Layer Hybrid Model¶

    本课程 / 教材采用 five-layer hybrid model（五层混合模型）：保留 OSI 模型中有用的分层思想，同时采用 TCP/IP 协议族在实践中的成功经验。

    层次 功能 例子
    Application layer 包含使用网络的程序 HTTP、DNS
    Transport layer 强化 network layer 的交付保证，提供适合应用的交付抽象 TCP 提供可靠 byte stream
    Network layer 把多条 link 组合成 networks，把多个 networks 组合成 internetworks，使远距离计算机之间可以传输 packets IP
    Link layer 在直接连接的计算机之间发送有限长度消息，并提供特定可靠性级别 Ethernet、802.11
    Physical layer 在不同介质上传输 bits，例如作为电信号或其他模拟信号 铜线、光纤、无线

    5 Standardization¶

    5. 1 Standards and Interoperability¶

    Standards（标准）定义互操作所需的内容：no more, no less。

    • Interoperability（互操作性）：计算机系统或软件交换并使用信息的能力。
    • Protocol standard：定义线上传输的协议，但通常不定义设备内部的 service interface，除非为了说明协议。
    • 好的 service interface / API 有助于协议推广，例如 Berkeley sockets。
    标准通常留下实现空间

    802.11 标准定义多种 transmission rates，但不规定发送方何时使用哪种速率。何时切换速率影响性能，是产品实现者竞争的空间。

    互操作组织
    • WiFi Alliance：围绕 802.11 标准推动产品互操作。
    • ONF（Open Networking Foundation）：在 Software-Defined Networking 场景中，开发标准和开源实现以保障可编程交换机控制协议的互操作。

    5. 2 De Facto and De Jure Standards¶

    类型 含义 例子
    De facto standard 没有正式规划，但因为实际使用而形成的标准 HTTP 早期、Bluetooth
    De jure standard 通过正式标准化组织规则采纳的标准 ITU、ISO、IETF、IEEE 制定的标准

    De facto standards 可能演化为 de jure standards。标准组织之间也可能互相认可标准，以扩大某项技术的市场。围绕特定技术形成的商业联盟也会参与标准发展，例如 3GPP（Third Generation Partnership Project）推动 UMTS / 3G 移动电话标准。

    5. 3 Telecommunications Standards¶

    ITU（International Telecommunication Union） 是重要的电信标准组织，主要包含三个部门：

    组织 全称 关注点
    ITU-T Telecommunications Standardization Sector 电话和数据通信系统标准；1993 年前称 CCITT
    ITU-R Radiocommunications Sector 协调全球无线电频率使用
    ITU-D Development Sector 推动信息通信技术发展，缩小数字鸿沟

    5. 4 International Standards¶

    ISO（International Standards Organization）也参与电信标准，并且是 ITU-T 成员。

    ISO 形成标准的一般流程为：

    CD (Committee Draft) -> DIS (Draft International Standard) -> IS (International Standard)
    • 某个国家标准组织提出国际标准需求后，成立 working group。
    • Working group 形成 CD 并分发给成员组织，通常给出约 6 个月评价期。
    • 若获得足够多数支持，形成 DIS 继续征求意见和投票。
    • 根据投票结果形成并发布 IS。
    • 在争议较大的领域，CD 或 DIS 可能经历多个版本，整个过程可能持续数年。

    5. 5 NIST and IEEE¶

    • NIST（National Institute of Standards and Technology）：美国商务部下属机构，为美国政府采购发布强制标准，国防部采购除外。
    • IEEE（Institute of Electrical and Electronics Engineers）：电气工程和计算领域的重要标准组织。
    • IEEE 802 Committee：标准化了多类 LAN；802.x 编号不保证成功，但 802.3（Ethernet） 和 802.11（Wi-Fi）影响巨大。

    5. 6 Internet Standards¶

    组织 全称 作用
    IAB Internet Architecture Board 负责 Internet 架构层面的指导
    IRTF Internet Research Task Force 面向长期研究问题
    IETF Internet Engineering Task Force 面向 Internet 工程标准
    W3C World Wide Web Consortium 制定 Web 标准

    课件给出的 Internet 标准演进路径为：

    Proposed Standard -> Draft Standard -> Internet Standard

    Rough consensus and running code

    David Clark 对 Internet 标准化的经典概括是 rough consensus and running code：既需要大致共识，也重视可运行实现。

    6 Policy, Legal, and Social Issues¶

    6. 1 Online Speech¶

    社交网络、论坛、内容分享网站和其他 user-generated content platforms 使用户能够表达观点，但也可能成为非法或冒犯性言论的传播渠道。

    • 关键矛盾是 censorship vs free speech。
    • 自动化、机器学习驱动的内容分类算法可能帮助识别版权侵权、仇恨言论等内容。
    • 但算法可能产生 false positives，把合法内容错误识别为非法或冒犯性内容。
    • 如果法律要求平台自动移除这类内容，可能导致 automated censorship。

    6. 2 Net Neutrality¶

    Network neutrality / net neutrality（网络中立性）主张：对于同一类型的应用流量，ISP 应提供同等服务质量，而不因内容发送者不同而区别对待。

    规则 含义
    No blocking 不阻断合法流量
    No throttling 不故意限制合法流量速率
    No paid prioritization 不通过付费方式购买优先级
    Transparency 公开可能被视为违反前三条的合理网络管理实践
    Net neutrality 不等于禁止所有优先级

    某些 reasonable network management practices 仍可能允许，例如在网络管理上优先处理实时游戏或视频会议流量。规则主要防止 ISP 出于反竞争目的阻断或限速竞争性服务，例如竞争性 VoIP 或视频服务。

    6. 3 Zero Rating¶

    Zero rating（零费率）指 ISP 按数据使用量向用户收费，但对特定服务免计流量。

    • 例如某移动运营商对某个社交应用或视频服务免流量费，以吸引用户。
    • Facebook 的 Free Basics 可视为这类实践的例子：将一组站点和服务打包为免费访问内容。
    • 争议在于 zero rating 会给某些服务或应用提供 preferential access，可能违反网络中立性精神。

    6. 4 Security¶

    问题 含义
    DDoS（Distributed Denial of Service） 大量网络机器同时向受害机器发送流量，试图耗尽其资源
    Botnet 被攻击者控制的大量受感染机器，可用于发起 DDoS
    Spam email 不受欢迎的电子邮件，课件指出其曾占据极高比例的邮件流量
    Phishing 伪装成可信方的邮件或消息，用于诈骗或窃取密码、银行卡等个人信息
    Identity theft 攻击者收集足够个人信息后冒用受害者身份
    IoT 带来的攻击面

    大量安全性较弱的 IoT devices 可能成为 DDoS 新来源。由于设备厂商、用户和网络运营商的激励并不一致，Internet security 很多问题都与 incentive structure 有关，可能需要新的监管或激励机制。

    6. 5 Privacy¶

    随着网络和联网设备普及，许多主体都能长期收集用户网络行为数据，用于 profiling and tracking。

    可能收集数据的主体包括：

    • ISP 和移动运营商
    • Applications 和 Web sites
    • Cloud hosting services 和 CDNs
    • Device manufacturers
    • Advertisers 和 Web tracking software vendors

    常见隐私问题：

    • Cookies：网站或广告商放置在浏览器中的小文件，可跨站追踪用户行为。
    • Browser fingerprinting：利用浏览器配置的独特性高概率识别用户。
    • Location privacy：移动系统厂商、移动运营商可以通过 GPS、气压计、蜂窝基站等推断用户位置。
    • Traffic source obfuscation：一些技术尝试隐藏用户流量来源，以提升隐私。

    6. 6 Disinformation¶

    Internet 让信息获取非常迅速，但其中也包含大量未经审慎验证、误导性甚至错误的信息。

    • 医疗建议可能来自专家，也可能来自完全不可靠来源。
    • Disinformation campaigns 会故意制造虚假故事，使读者相信未发生的事情。
    • 网络和平台运营者面临三个难题：
      • 如何定义 disinformation？
      • 能否可靠检测 disinformation？
      • 一旦检测到，应当采取什么措施？

    7 Metric Units¶

    网络中常见单位需要区分 bytes 和 bits/sec。

    单位 课件约定 含义
    KB \(2^{10}\) bytes Kilobyte
    MB \(2^{20}\) bytes Megabyte
    GB \(2^{30}\) bytes Gigabyte
    TB \(2^{40}\) bytes Terabyte
    kbps \(10^3\) bits/sec kilobits per second
    Mbps \(10^6\) bits/sec megabits per second
    Gbps \(10^9\) bits/sec gigabits per second
    Tbps \(10^{12}\) bits/sec terabits per second

    b 与 B

    • 小写 b 通常表示 bit。
    • 大写 B 通常表示 byte。
    • \(1 \, \text{B} = 8 \, \text{b}\)，因此 KBps 与 kbps 不是同一个单位。
